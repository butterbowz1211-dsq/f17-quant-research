# A 股数据采购与验收清单

用途：替换当前 BaoStock/AkShare 拼接数据，支持 2010-01-01 至 2026-09-28 的日频横截面研究，并最终通过严格执行验收。不是所有字段都必须来自同一供应商，但主键、证券主表和公司行动必须能互相对账。

## 一句话要求

买“含退市股、日级 ST/停牌/涨跌停、原始价与复权因子、分红送转/并购/退市结算、历史流通股本”的**点时（point-in-time）全历史**，不要只买当前上市股票的行情。

## 必须项

| 数据 | 最小字段 | 关键要求 |
|---|---|---|
| 证券主表 | symbol、交易所、板块、上市日、退市日、证券类型、名称变更、代码变更 | 覆盖已退市/被并购证券；代码变更要给出旧码、新码、生效日；不能只给当前股票池 |
| 日行情 | date、symbol、open/high/low/close、pre_close、volume、amount、turnover | 原始未复权价与成交量额；停牌日要明确标记，不能把停牌日直接删掉 |
| 复权 | 复权因子或 qfq/hfq 价格、复权基准日 | 因子必须可回溯；不能只给一条无法对账的复权收盘价 |
| 交易状态 | tradestatus、停牌原因、ST/*ST/PT 标记、风险警示变更日 | 日级，不是月末快照；必须能还原“当日开盘时是否可交易” |
| 涨跌停 | 当日涨停价、跌停价、是否无涨跌幅限制 | 按板块/ST/上市首日规则给实际限价；不能只用收盘价反推 |
| 公司行动 | 除权除息日、记录日、派息日、每股现金、送转比例、配股、并购换股、退市结算 | 每个事件唯一 ID；现金分红要含税基/到账口径；退市要有终值或结算价 |
| 股本 | 当时流通股本、总股本、自由流通股本（如有） | 历史点时值；不能只用当前股本回填 |
| 行业/指数 | 历史行业分类、指数成分及权重（至少基准） | 有生效日；静态行业只能作辅助 |
| 交易日历 | 全市场交易日、临时休市 | 与交易所口径一致 |

## 点时与生存偏差

- 每个交易日股票池必须包含当日仍可交易、后来退市的证券；不能用“今天还活着”的股票池回看历史。
- ST、停牌、涨跌停、上市天数、流通股本都必须是**当日已知**，不能用未来数据回填。
- 退市不是“收益为 0 或缺失”：要有退市整理期/最后交易日/现金结算或换股对价，否则标签会系统性偏差。
- 代码变更、并购换股要能追溯，不能把旧码和新码简单拼接成一条价格序列。

## 采购时问供应商的 8 个问题

1. 是否包含 2010 年以来所有已退市 A 股？退市后的最后交易日和结算方式是什么？
2. ST/*ST 是日级还是月末/公告日快照？能否给风险警示开始/结束日期？
3. 停牌日是删除还是保留？停牌期间 pre_close、复权因子怎么处理？
4. 涨跌停价是交易所原始值还是按收盘价反推？是否覆盖新股/ST/北交所不同规则？
5. 复权因子是累计因子还是单次事件因子？能否用原始价和因子逐日对账？
6. 分红送转是否含税？有没有 record/ex/pay 三个日期和每股比例？
7. 流通股本是历史值时点还是当前值？缺失年份怎么处理？
8. 能否提供数据字典、覆盖率报告、主键唯一性校验和 SHA256？

## 验收检查

- 主键 `(date, symbol)` 唯一；证券主表覆盖行情中出现的所有代码，反之亦然。
- 交易日历与交易所一致；停牌/ST/涨跌停字段无未知值，或未知值被明确标出。
- 原始 OHLC 与成交量额单位自洽；复权价 × 原始价关系可解释。
- 随机抽 100 只（含 20 只退市股）逐年核对：上市日、退市日、ST 区间、分红送转、停牌日。
- 用同一套规则重算本文 17 个因子，确认没有因为复权/股本/状态缺失产生整段 NaN。
- 任何一项不能对账，就不能把 `execution_accepted` 设为 true；研究模式仍可保留 limitations。

## 交付格式

优先 Parquet（按年分区）+ CSV 证券主表/公司行动；附 `manifest.json`（字段、行数、日期范围、SHA256）和 `data_dictionary.md`。先给 100 只样本（含退市、ST、停牌、送转各若干）做验收，再给全量。

## 当前状态
