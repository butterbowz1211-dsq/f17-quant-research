# 后续数据补全与验收契约

本次 `derived/source_union_v1`、AkShare CSV 与候选事件都不是可直接通过的训练包。不能通过把未知状态设成 False、空分红设成零、复权因子设成 1 来满足接口。

## 已验证源目录

`prepare.py --source` 需要：

1. `calendar.csv`：列 `date`，全球实际交易日历，从固定锚点 2010-01-04 开始，无重复、递增。额外早期指标历史需在后续版本显式接入，不移动现有决策相位。
2. `market.parquet`：唯一 `(date,symbol)`，字段如下。
3. `actions.json`：逐事件公司行动。
4. `source_acceptance.json`：源数据状态及上述三个文件 SHA256。必须有实际逐项核验依据。

| 字段 | 口径 |
|---|---|
| `symbol` | sh600000 / sz000001，保留历史证券 |
| `exchange`, `security_type` | SH/SZ 与 A；不能只按代码前缀把存托凭证等当 A 股 |
| `raw_open/high/low/close` | 元/实际股份，未复权 OHLC；缺失不制造交易价 |
| `raw_volume`, `raw_amount` | 股、人民币元；Tushare 原始手/千元分别×100/×1000 |
| `adjusted_open/high/low/close` | 经核验一致复权口径；不能直接替代成交价 |
| `adjustment_verified` | 该日该证券调整路径已核验，不是“接口返回了数” |
| `float_shares`, `turnover` | 当时可得流通股份数、日股份换手率小数 |
| `listing_date` | 实际上市日期，不能用面板首次出现推断 |
| `is_st` | 当日状态，未知保留缺失；月末快照不等于日级完整覆盖 |
| `industry` | 历史行业；若仅静态代理必须披露来源/用途 |
| `status` | `trading/suspended/delisted/unknown`；交易状态指开盘时已知 |
| `limit_up_price/limit_down_price`, `no_limit` | 当日实际限价或经验证无涨跌幅限制，不用 VWAP 推断 |

每个派息/送转事件需唯一 `id`、`symbol`、`kind="cash_stock_distribution"`、`verified`、`record_date`、`ex_date`、`pay_date`、`stock_date`、`gross_cash_per_share`、`net_cash_per_share`、`share_ratio`。比例按每股：10 送 2 转 3 是 share_ratio=1.5，10 派 3 是 gross_cash_per_share=0.3。

净额必须有税收/账户假设依据。股份到账日在有送转时不可省略；不适用的零现金/零新增股份事件须在标准化层明确标识，不能把日期缺失都当作除权日。引擎不支持的配股、合并换股、逆向拆股和退市终值事件应阻断验收，不能删掉证券绕开。

## BaoStock 日级状态补充（supplement_v1）

为降低“月末 ST 快照”误差，新增独立的 `supplement.py`，只补日级 `isST`、`tradestatus` 和原始价量，不改写 `source_union_v1`，也不生成执行验收：

- `derived/supplement_v1/security_master.parquet`：BaoStock `query_stock_basic` 的证券主表；`type=1` 且 `is_stock=True` 的 5,563 只股票参与下载。
- `bars/<symbol>.parquet`：单只 2010-01-01—2026-09-28 日线，字段 `date,code,raw_open,raw_high,raw_low,raw_close,raw_pre_close,raw_volume,raw_amount,turnover,is_st,daily_status`；`turnover=turn/100`，`daily_status` 取 `trading/suspended`。
- `by_year/<year>.parquet`：按年合并的紧凑分区，供 `prepare_research.py --supplement` 读取。
- `coverage.csv`：逐证券 `status=ok/empty/not_downloaded`、行数、首末日期、停牌/ST/未知状态天数。历史在 2026-09-28 之前结束（退市或长期停牌）是合法结果，必须保留其真实 `last_date`，不得把“末日早于 END”误判成丢页而递归切分。
- `manifest.json`：字段、起止日期、证券数、行数、年度文件 SHA256、`execution_accepted=false`；`symbols/downloaded_symbols/empty_symbols/not_downloaded_symbols` 与 `complete`（仅当 `downloaded+empty==symbols` 才为 true）。
- `download_ledger.jsonl`：逐证券成功/空/错误/跳过记录，用于断点续传和错误重试。

接入规则：`prepare_research.py` 的 `supplemental()` 把 supplement 原始表放在来源优先级最后，按 `(date,symbol)` 覆盖同日字段；`metadata()` 用 supplement 主表补上市/退市日期。规范化层新增 `st_source`：`1` 表示该行有日级 `isST`，`2` 表示仍用月末快照，`0` 表示未知。`quality_report.json` 记录 `eligible_st_source` 与 `supplement` 摘要；缺失的日级状态不会被填成 `False`。

覆盖台账的 `empty` 表示供应商确认该证券在请求窗口无行情，不等于“缺失已补齐”；`not_downloaded` 表示尚未成功请求。两者都不能在执行验收中当作通过。

## 准备后样本包

`prepare.py` 产出 `samples.npz`、清洗前后因子 Parquet、缺失标签原因表、执行用 `market.parquet`、`actions.json` 和输入清单哈希。默认 `acceptance.json` 是 `REVIEW_REQUIRED`。

七项关卡均需 `status=PASS`、`evidence`（包内相对文件名）与 `sha256`：

- `security_coverage`：历史证券主表、遗漏证券分类、上市/退市/转换处理。
- `raw_prices_units`：主键、原始 OHLC、单位、异常及来源。
- `adjustment_actions`：复权与分红送转、到账及退市处理对账。
- `daily_status`：历史 ST、停牌、开盘权限/涨跌停，不使用当日未来高低价决定成交。
- `factor_lineage`：17 个公式、字段、时点和历史覆盖。
- `label_coverage`：标签边界、缺失原因，退市/暴跌/低流动性集中性分析。
- `execution_tests`：工程测试及真实数据账本对账证据。

这些是证据链要求，不是七个形式开关。当前项目不能满足全部关卡，因此根目录 `acceptance.json` 保持 BLOCKED。
